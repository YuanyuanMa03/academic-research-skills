## 二、scansci-pdf 下载链路细节（本次最有价值的实测）

**成功路径**：`get 10.1002/smll.202303319 --strategy legal_only` → 11 源对冲级联 → Unpaywall 后到命中（"late result" 等待窗口起效）→ 自动按 `作者_年份_标题` 重命名 → 报告实际来源 Unpaywall。与 SKILL.md 描述逐项吻合。

**失败路径同样有价值**（3 例，全部结构化报错而非静默失败）：
1. 未配置邮箱：Unpaywall 渠道报 `config_needed`，提示"询问用户邮箱后配置重试"——按提示 `config-cmd email` 后重试即成功。
2. 2021 年 Wiley 文章无 OA 副本：报"无 PDF"，建议机构通道。
3. Wiley/RSC 的 OA 页面型文章：浏览器后端（patchright/camoufox 可选组件）未装时跳过浏览器策略 → 失败。

**结论**：`legal_only` 合规策略下，"Unpaywall 有 PDF 直链"的文章开箱即得；出版社页面型 OA 与付费文章需要可选浏览器组件或机构通道——SKILL.md 安装引导与排障表描述准确。

## 三、测试发现的技能改进点（建议）

1. **scansci-pdf search 相关性**：长复合查询（"photorechargeable lithium battery semiconductor cathode"）被宽泛匹配到回收主题。建议在桥接 SKILL.md 的路由表加一句使用提示："检索精度优先时用 PubMed（pm-search）；跨源发现用 scansci-pdf search，结果需相关性过滤"。
2. **CLI 兜底时引文缺位**：`citation` 仅 MCP 提供；CLI `get` 的自动 BibTeX 未在输出目录出现。建议排障表补一行："CLI 模式需要 BibTeX 时用 `scansci-pdf bibtex`（若版本支持）或装 MCP server"。
3. **OA 覆盖提示**：安装引导可加一句——`pip install scansci-pdf[camoufox]` 可显著扩大无机构通道时的 OA 覆盖（本次 2/3 失败源于浏览器组件缺失）。
4. **PubMed 主题边界**：材料/物理课题在 PubMed 覆盖有限（光充电方向仅 6 条），arXiv/CrossRef 类源是必要补充——这印证了 REFERENCE.md 双检索入口设计的必要性。

## 五、总体判断

新工作流（平台检索 → scansci-pdf 获取 → nature 写作）在本机真实可用：检索、合法下载、全文转换、三段式学术写作全部实测通过。当前环境的主要限制是浏览器类技能无法在 ZCode 会话内直接运行（需目标宿主复测），以及 scansci-pdf 可选浏览器组件未安装时 OA 覆盖收窄——两者都有明确的使用边界文档支撑，不构成阻断。
